# Tibo Reset Watch 部署与发布完整教案

本文用于完成以下工作：

1. 第一次把项目部署到中国服务器。
2. 配置 Cloudflare Browser Run，让中国服务器可以生成 X 原生页面截图。
3. 把独立网页版本发布到 Cloudflare Pages。
4. 以后修改代码后，安全发布到 208 和 Cloudflare Pages。
5. 出现问题时完成检查、回滚和凭据轮换。

文中的账号、Token、私钥、服务器地址均使用占位符。任何真实密钥都不能写进 Git、README、示例配置、截图或聊天记录。

## 一、先理解部署结构

本项目有两个独立发布目标，它们不会自动同步：

```text
用户浏览器
   |
   +--> 中国服务器 208：http://39.98.37.208:9104/
   |       |
   |       +--> Node.js：网页、翻译接口、回复上下文接口
   |       +--> Cloudflare Browser Run REST API：打开 X 并生成原生截图
   |       +--> 本地持久化缓存：译文、X 截图、最近动态快照（默认位于译文目录的 feed 子目录）
   |
   +--> Cloudflare Pages：https://tibo-reset-watch.pages.dev/
           |
           +--> 静态网页
           +--> Pages Advanced Mode _worker.js：同源 feed、公开订阅信号、公共翻译、可选 AI 翻译
           +--> 不配置中国服务器的 Browser Run Token，不提供 X 原生截图
```

建议把 208 作为主站：

- 中国服务器访问稳定，能保存译文和截图缓存。
- Cloudflare Browser Run 在境外打开 X，解决中国服务器无法直接稳定打开 X 的问题。
- Cloudflare Pages 作为可选公网镜像；Pages 与 208 必须分别发布。

截至 2026-09-22，208 已核实的运行信息如下：

| 项目 | 当前值 |
| --- | --- |
| 操作系统 | Ubuntu 22.04 x86_64 |
| Node.js | 22.23.2 |
| systemd 服务 | `tibo-reset-watch.service` |
| 对外端口 | `9104` |
| 发布根目录 | `/data/tibo-reset-watch` |
| 当前版本链接 | `/data/tibo-reset-watch/current` |
| 版本目录 | `/data/tibo-reset-watch/releases/<版本号>` |
| 私有配置 | `/data/tibo-reset-watch/translation.env` |
| 译文缓存 | `/data/tibo-reset-watch/translations` |
| X 截图缓存 | `/data/x-screenshots` |
| 运行用户 | `tibo-watch` |

这些值是当前服务器的实际配置。换服务器时，应重新核对路径、端口、CPU 架构和 systemd 单元。

## 三、208 第一次安装

日常使用的 `deploy-208.cmd` 和 `scripts/deploy-208.ps1` 只适用于已经完成首次安装的服务器。新服务器需要先准备运行时、目录、配置、首个版本和 systemd 服务。

### 3.1 创建运行用户和目录

使用具备 root 权限的服务器终端执行：

```bash
sudo useradd --system --home /nonexistent --shell /usr/sbin/nologin tibo-watch
sudo install -d -o root -g root -m 755 /data/tibo-reset-watch
sudo install -d -o root -g root -m 755 /data/tibo-reset-watch/releases
sudo install -d -o root -g root -m 755 /data/tibo-reset-watch/runtime
sudo install -d -o tibo-watch -g tibo-watch -m 700 /data/tibo-reset-watch/translations
sudo install -d -o tibo-watch -g tibo-watch -m 700 /data/x-screenshots
```

如果 `tibo-watch` 已存在，`useradd` 会提示用户已存在，此时不要重复创建。

### 3.2 安装 Node.js 22

项目要求 Node.js 22 或更高版本。当前 208 使用 Node.js 22.23.2 的 Linux x64 官方压缩包，目录结构为：

```text
/data/tibo-reset-watch/runtime/
├── node-v22.23.2-linux-x64/
└── current -> node-v22.23.2-linux-x64
```

从 Node.js 官方站点下载与服务器架构匹配的 Node.js 22 压缩包，同时下载 `SHASUMS256.txt`。完成 SHA-256 校验后解压，并创建 `current` 软链接。不要在 ARM64 服务器使用 `linux-x64` 包。

当前 Ubuntu x86_64 服务器可以按下面的方式安装；将来升级时，把版本号改成计划使用的 Node.js 22 版本：

```bash
NODE_VERSION=v22.23.2
cd /data/tibo-reset-watch/runtime
sudo curl -fLO "https://nodejs.org/dist/$NODE_VERSION/node-$NODE_VERSION-linux-x64.tar.xz"
sudo curl -fLO "https://nodejs.org/dist/$NODE_VERSION/SHASUMS256.txt"
grep " node-$NODE_VERSION-linux-x64.tar.xz$" SHASUMS256.txt | sha256sum -c -
sudo tar -xJf "node-$NODE_VERSION-linux-x64.tar.xz"
sudo ln -sfn "node-$NODE_VERSION-linux-x64" current
```

校验结果必须显示 `OK` 后才能解压和切换软链接。

验证：

```bash
/data/tibo-reset-watch/runtime/current/bin/node --version
```

输出必须是 `v22.x.x` 或更高兼容版本。

### 3.3 创建私有环境配置

以仓库中的 `server/translation.env.example` 为模板，在服务器创建：

```text
/data/tibo-reset-watch/translation.env
```

208 的推荐内容：

```dotenv
HOST=0.0.0.0
PORT=9104
TRANSLATION_CACHE_DIR=/data/tibo-reset-watch/translations

X_SCREENSHOT_CACHE_DIR=/data/x-screenshots
CLOUDFLARE_ACCOUNT_ID=<Cloudflare Account ID>
CLOUDFLARE_BROWSER_API_TOKEN=<只保存在服务器上的 Browser Run Token>

AI_TRANSLATION_URL=
AI_TRANSLATION_MODEL=
AI_TRANSLATION_API_KEY=
```

设置权限：

```bash
sudo chown root:root /data/tibo-reset-watch/translation.env
sudo chmod 600 /data/tibo-reset-watch/translation.env
```

说明：

- `CLOUDFLARE_ACCOUNT_ID` 不是 Zone ID。
- `CLOUDFLARE_BROWSER_API_TOKEN` 必须具有 `Browser Rendering - Edit` 权限。
- AI 翻译不是必填；未配置时，公共翻译和英文卡片仍可使用。
- 不要把服务器私有配置复制回 `server/translation.env.example`。

### 3.4 上传首个发布版本

在本地项目目录先验证：

```powershell
npm.cmd run web:check
npm.cmd run translation:check
node.exe --check cloudflare/worker.mjs
git diff --check
```

首个发布包需要包含以下 12 个文件：

```text
package.json
server/web-server.cjs
server/feed-service.mjs
server/reset-calendar.mjs
web/app.js
web/config.js
web/favicon.svg
web/index.html
web/manifest.webmanifest
web/post-cards.js
web/styles.css
web/sw.js
```

把它们解压到：

```text
/data/tibo-reset-watch/releases/<首个版本号>/
```

上传前计算本地压缩包 SHA-256；上传后在服务器用 `sha256sum` 重新计算并比较。两边一致后才能解压。日常更新不需要手工完成这些步骤，`deploy-208.ps1` 会自动生成清单并逐文件校验。

然后创建软链接：

```bash

```

`current` 必须指向 `/data/tibo-reset-watch/releases/` 下的真实版本目录。

### 3.5 创建 systemd 服务

创建 `/etc/systemd/system/tibo-reset-watch.service`：

```ini
[Unit]
Description=Tibo Reset Watch web and translation
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=tibo-watch
Group=tibo-watch
WorkingDirectory=/data/tibo-reset-watch/current
EnvironmentFile=/data/tibo-reset-watch/translation.env
ExecStart=/data/tibo-reset-watch/runtime/current/bin/node server/web-server.cjs
Restart=on-failure
RestartSec=5
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
PrivateTmp=true
ReadWritePaths=/data/tibo-reset-watch/translations
AmbientCapabilities=CAP_NET_BIND_SERVICE
CapabilityBoundingSet=CAP_NET_BIND_SERVICE
UMask=0077

[Install]
WantedBy=multi-user.target
```

创建 `/etc/systemd/system/tibo-reset-watch.service.d/x-screenshot.conf`：

```ini
[Service]
ReadWritePaths=/data/x-screenshots
```

加载并启动：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now tibo-reset-watch.service
sudo systemctl status tibo-reset-watch.service --no-pager
```

## 四、Cloudflare Browser Run 配置详解

Cloudflare 产品名称现在显示为 Browser Run，API 路径仍是 `browser-rendering`。本项目使用 REST API 的 `/screenshot` Quick Action。

### 4.1 本项目为什么需要它

中国服务器本身不适合直接访问 X。Node 服务会把可信 feed 中的 Tibo 帖子 URL 交给 Cloudflare Browser Run，由 Cloudflare 的境外浏览器打开页面并截取首个 `article`。

完整调用链：

```text
用户点击“下载 X 原文截图”
  -> 208 的 /api/x-screenshot?id=<帖子ID>
  -> 校验帖子必须来自当前可信 feed 且作者是 @thsottiaux
  -> 检查 /data/x-screenshots/<帖子ID>.png
  -> 未命中缓存时调用 Cloudflare Browser Run /screenshot
  -> 校验返回内容是有效 PNG 且不超过 12 MiB
  -> 写入缓存并返回给用户
```

该 Token 只保存在 208 的 `translation.env`，不会下发给浏览器，也不会进入 Cloudflare Pages 上传包。

### 4.2 获取 Account ID

方法一，适合所有账号：

1. 登录 Cloudflare 控制台。
2. 按 `Ctrl + K` 打开搜索。
3. 输入 `Copy account ID`。
4. 点击搜索结果复制 Account ID。

方法二：

1. 进入 `Workers & Pages`。
2. 找到 `Account Details`。
3. 复制 `Account ID`。

不要复制 Zone ID。Account ID 用于以下 API 路径：

```text
https://api.cloudflare.com/client/v4/accounts/<ACCOUNT_ID>/browser-rendering/screenshot
```

### 4.3 创建最小权限 API Token

推荐创建独立 Token，不要使用 Global API Key，也不要复用 Pages 发布 Token。

控制台操作：

1. 进入 `Manage Account` > `Account API Tokens`。
2. 点击 `Create Token`。
3. 选择 `Custom Token`。
4. Token 名称填写：`tibo-reset-watch-browser-run`。
5. Permissions 选择：
   - 类型：`Account`
   - 权限：`Browser Rendering`
   - 级别：`Edit`
6. Account Resources 只选择运行本项目的那个 Cloudflare Account。
7. 可选：设置有效期。生产长期运行可设置较长有效期，并提前安排轮换。
8. 可选：服务器出口 IP 固定时，可以添加 IP 限制；出口 IP 不稳定时不要随意限制，否则截图会突然全部失败。
9. 点击 `Continue to summary`，确认只有 Browser Rendering 权限。
10. 点击 `Create Token`。
11. 立即复制 Token。Cloudflare 只显示一次。

Token 必须存放在密码管理器或服务器私有配置中。不能放在：

- `server/translation.env.example`
- README 或本教案
- Git 提交
- Cloudflare Pages ZIP
- 浏览器前端代码
- 截图、聊天记录或工单

### 4.4 把凭据写入 208

在服务器使用 `sudoedit /data/tibo-reset-watch/translation.env`，填写：

```dotenv

CLOUDFLARE_BROWSER_API_TOKEN=<新建的 Token>

确认目录和配置权限：

```

### 4.5 验证 Browser Run

第一步，检查功能是否被配置：

```bash
curl -fsS http://127.0.0.1:9104/api/x-screenshot-status
```

预期：

```json
{"enabled":true}
```

这个接口只能证明三个配置项都存在，不能证明 Token 一定有效。

第二步，打开主站，从当前动态中找一个 Tibo 帖子 ID，然后真实生成截图：

```bash
curl -fS "http://127.0.0.1:9104/api/x-screenshot?id=<当前可信帖子ID>" -o /tmp/tibo-x-test.png
file /tmp/tibo-x-test.png
```

预期 `file` 识别为 PNG。测试 ID 必须来自当前页面的 Tibo 原帖，随便填写的 ID 会被服务拒绝。

第三步，浏览器打开 `生成分享图`，确认出现：

```text
下载 X 原文截图
```

点击后检查图片是否只包含 X 的帖子区域，而不是整张浏览器页面。

### 4.6 用量、限流和常见错误

Cloudflare Workers Free 计划当前包含每天 10 分钟 Browser Run 用量；Quick Actions 的免费计划限制为每 10 秒 1 次请求。具体额度可能变化，应以 Cloudflare 控制台和官方文档为准。

本项目自身还有限制：

- 同一时间只生成 1 张新截图。
- 每分钟最多向 Cloudflare 发起 6 次新请求。
- 相同帖子并发请求会合并。
- 成功图片会写入本地缓存，重复下载不再调用 Cloudflare。

常见问题：

| 表现 | 常见原因 | 处理方法 |
| --- | --- | --- |
| 按钮完全不显示 | 三项截图配置缺少任意一项 | 检查 `translation.env`，重启服务 |
| HTTP 401/403 | Token 错误、过期或权限不是 Browser Rendering Edit | 新建最小权限 Token 后轮换 |
| HTTP 429 | Cloudflare 免费额度或速率限制；也可能命中应用自身限制 | 等待后重试，检查 Browser Run 用量 |
| HTTP 502 | X 页面拦截机器人、Cloudflare 未返回有效 PNG | 稍后重试；英文/中文内容卡片仍可用 |
| HTTP 504 | X 页面或 Browser Run 超时 | 稍后重试，检查 Cloudflare 状态 |
| 首次慢、以后快 | 第一次需要境外浏览器渲染，之后读取本地缓存 | 正常现象 |

Cloudflare 明确说明 Browser Run 请求会被目标站点识别为机器人，因此 Token 正确也不保证 X 永远允许访问。

### 4.7 Token 泄露或轮换

发现 Token 出现在 Git、示例文件、聊天或截图中时，不要只删除文本，必须轮换：

1. 创建一个新的 `Browser Rendering - Edit` Token。
2. 把新 Token 写入 208 的 `translation.env`。
3. 重启服务并真实生成一张新截图。
4. 确认新 Token 可用后，在 Cloudflare 控制台撤销旧 Token。
5. 再次检查仓库：

```powershell
rg -l "CLOUDFLARE_BROWSER_API_TOKEN=(cfat_|cfut_|[A-Za-z0-9_-]{30,})|cfat_[A-Za-z0-9_-]{40,}|cfut_[A-Za-z0-9_-]{40,}" --glob "!node_modules/**" --glob "!.git/**" .
```

命令不应返回任何项目文件。

## 五、Cloudflare Pages 第一次发布

Pages 是独立镜像。发布 Pages 不会更新 208；发布 208 也不会更新 Pages。

### 5.1 生成专用上传包

首次或 package-lock.json 变化后先执行 `npm.cmd ci`，安装锁定版本的 esbuild；它将共享 feed 模块与 Worker 打包成单个 `_worker.js`。然后在项目根目录执行：

```powershell
pwsh.exe -NoProfile -File scripts/build-pages.ps1
```

脚本会输出：

```text
PAGES_DIRECTORY=<临时站点目录>
PAGES_ZIP=<临时 ZIP 路径>
```

上传包只包含：

- `web/` 静态资源
- `_worker.js`
- `_routes.json`
- `_headers`

不会包含服务器配置、Token、SSH 私钥和本地缓存。

### 5.2 控制台创建 Direct Upload 项目

1. 登录 Cloudflare 控制台。
2. 进入 `Workers & Pages`。
3. 点击 `Create application` > `Get started` > `Drag and drop your files`。
4. 项目名填写 `tibo-reset-watch`。
5. 上传 `PAGES_ZIP` 指向的 ZIP，或拖入 `PAGES_DIRECTORY` 目录。
6. 点击 `Deploy site`。
7. 首次部署完成后访问 `https://tibo-reset-watch.pages.dev/`。

本项目使用 Advanced Mode `_worker.js`。Cloudflare 官方支持通过控制台 Direct Upload 上传 `_worker.js`；普通 `/functions` 目录不能用同样方式编译上传。

Direct Upload 项目以后可以继续使用控制台或 Wrangler 发布，但不能原地切换成 Git 集成；若将来要 Git 自动发布，需要新建一个 Git 集成项目。

### 5.3 Pages 的变量和 Secret

公共 MyMemory 翻译不需要变量。

需要 AI 翻译时：

1. 进入 Pages 项目。
2. 打开 `Settings` > `Variables and Secrets` > `Add`。
3. 添加普通变量：
   - `AI_TRANSLATION_URL`
   - `AI_TRANSLATION_MODEL`
4. 添加 Secret：
   - `AI_TRANSLATION_API_KEY`
5. 对 API Key 选择 `Encrypt`。
6. 保存后创建一次新部署。

不要把 AI API Key 写进 `_worker.js`、ZIP 或 Git。

Pages 不需要也不应该配置：

```text
CLOUDFLARE_BROWSER_API_TOKEN
X_SCREENSHOT_CACHE_DIR
```

因此 Pages 上不显示“下载 X 原文截图”属于预期行为。

### 5.4 Pages 验收

至少检查：

```text
https://tibo-reset-watch.pages.dev/
https://tibo-reset-watch.pages.dev/api/translation-status
https://tibo-reset-watch.pages.dev/api/x-screenshot-status
```

预期：

- 首页正常加载真实动态。
- `translation-status` 中 `public` 为 `true`；AI 取决于是否配置。
- `x-screenshot-status` 返回 `enabled:false`。
- 英文图片可以生成。
- 公共翻译有额度时，中文译文和中英对照可以生成。
- 桌面和手机宽度没有横向溢出。
- 浏览器控制台没有相关错误。

MyMemory 返回 429 表示公共翻译供应商额度耗尽，不表示 Pages 发布失败。

## 七、回滚

### 7.1 208 自动回滚

`deploy-208.ps1` 在新版本切换后如果本机健康检查失败，会自动恢复旧版 `current` 链接并重启服务。看到部署脚本失败时，不要立即重复发布，先查看完整错误和当前链接：

```bash
readlink -f /data/tibo-reset-watch/current
systemctl status tibo-reset-watch.service --no-pager
journalctl -u tibo-reset-watch.service -n 100 --no-pager
```

### 7.2 208 手动回滚

只有确认目标目录属于 `/data/tibo-reset-watch/releases/` 后才执行：

```bash
readlink -f /data/tibo-reset-watch/current
ls -1dt /data/tibo-reset-watch/releases/*
sudo ln -s /data/tibo-reset-watch/releases/<上一版本> /data/tibo-reset-watch/.manual-rollback
sudo mv -Tf /data/tibo-reset-watch/.manual-rollback /data/tibo-reset-watch/current
sudo systemctl restart tibo-reset-watch.service
curl -fsS http://127.0.0.1:9104/api/translation-status
```

不要删除当前或历史版本来实现回滚。

### 7.3 Cloudflare Pages 回滚

1. 进入 Pages 项目的 `Deployments`。
2. 在 `All deployments` 中找到上一个成功的 Production 部署。
3. 点击该部署右侧三点菜单。
4. 选择 `Rollback to this deployment`。
5. 确认后重新验收首页和接口。

Preview 部署不能作为生产回滚目标。

## 八、故障排查速查表

| 问题 | 先检查什么 | 常用命令或位置 |
| --- | --- | --- |
| 双击部署一闪而过 | 是否安装 PowerShell 7 | `pwsh.exe -Version` |
| 找不到 SSH 私钥 | 默认路径是否存在 | `Test-Path "$env:USERPROFILE\.ssh\id_ed25519_codex_39_98_37_208"` |
| SSH Permission denied | 公钥、用户名、端口 | `ssh.exe -i <私钥> root@39.98.37.208 true` |
| 208 返回 502/503 | systemd 日志和环境配置 | `journalctl -u tibo-reset-watch.service -n 100` |
| 截图按钮不显示 | `/api/x-screenshot-status` | 检查三项截图配置并重启 |
| 截图返回 429 | Cloudflare Browser Run 用量/速率 | Cloudflare `Browser Run` 页面 |
| 中文翻译返回 429 | MyMemory 每日额度 | 稍后重试或配置 AI 翻译 |
| Pages 首页正常但翻译失败 | 不要把静态发布成功当成 API 验收 | 检查 `/api/translation-status` 和浏览器控制台 |
| 页面仍是旧版 | PWA Service Worker 缓存版本未增加 | 修改 `web/sw.js` 的 `CACHE_NAME` 后重新发布 |
| Pages 没有 X 截图按钮 | 这是当前设计 | X 原生截图只在 208 Node 服务启用 |
